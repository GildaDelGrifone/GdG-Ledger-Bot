# Guida Operativa API e Configurazione (GdG-Ledger-Bot)

Questo documento fornisce le istruzioni dettagliate passo-passo per ottenere le chiavi API necessarie, configurare Satispay Business, Google Sheets e impostare il tunnel Cloudflare per l'esecuzione in locale.

---

## 1. Come ottenere le credenziali per Google Sheets API

Per consentire al bot di leggere e scrivere sul foglio di calcolo senza richiedere login manuale ad ogni avvio, utilizziamo un **Service Account** di Google Cloud.

### Passo 1: Crea un progetto su Google Cloud Console
1. Accedi a [Google Cloud Console](https://console.cloud.google.com/) con il tuo account Google.
2. Clicca sul selettore dei progetti in alto e seleziona **"Nuovo Progetto"**.
3. Dai un nome al progetto (es. `GdG-Ledger-Bot`) e clicca su **Crea**.

### Passo 2: Abilita le API di Google Drive e Google Sheets
1. Nel menu laterale, vai su **"API e servizi"** > **"Libreria"**.
2. Cerca **"Google Sheets API"**, cliccaci sopra e seleziona **Abilita**.
3. Torna nella libreria, cerca **"Google Drive API"**, cliccaci sopra e seleziona **Abilita**.

### Passo 3: Crea il Service Account e scarica la chiave JSON
1. Nel menu laterale, vai su **"API e servizi"** > **"Credenziali"**.
2. Clicca su **"+ CREA CREDENZIALI"** in alto e seleziona **"Account di servizio"** (Service Account).
3. Inserisci un nome (es. `bot-ledger-service-account`) e clicca su **Crea e continua**.
4. Come ruolo puoi assegnare `Editor` o proseguire cliccando su **Continua** e poi **Fine**.
5. Clicca sull'account di servizio appena creato nella lista delle credenziali.
6. Vai nella scheda **"Chiavi"** (Keys).
7. Clicca su **"Aggiungi chiave"** > **"Crea nuova chiave"**.
8. Seleziona il formato **JSON** e clicca su **Crea**.
9. Verrà scaricato un file `.json` sul tuo computer. Rinominalo in `credentials.json` e posizionalo nella cartella principale del bot (`/home/destard/Code/GdG-Ledger-Bot/`).

### Passo 4: Condividi il Foglio Google con il Service Account
1. Apri il file `credentials.json` e copia l'indirizzo email presente nel campo `"client_email"` (es: `bot-ledger-service-account@gdg-ledger-bot.iam.gserviceaccount.com`).
2. Apri il tuo foglio di calcolo su Google Drive.
3. Clicca sul pulsante **"Condividi"** in alto a destra.
4. Incolla l'email del Service Account, assegna il permesso **"Editor"** e deseleziona "Invia notifica", poi conferma con **Condividi**.
5. Copia l'ID del foglio dall'URL del browser:
   `https://docs.google.com/spreadsheets/d/<ID_DEL_FOGLIO>/edit`
6. Inserisci questo ID nel file `.env`:
   ```env
   GOOGLE_SPREADSHEET_ID="ID_DEL_FOGLIO"
   GOOGLE_WORKSHEET_NAME="Transazioni"
   ```

## 2. Come ottenere e configurare le API Satispay Business

Satispay utilizza un'architettura crittografica asimmetrica (RSA con HTTP Signatures): non usa una semplice API key statica, ma un **KeyID** associato a una coppia di chiavi privata/pubblica generata da te.

### Passo 1: Ottieni il Token di Attivazione dal Dashboard Satispay
1. Accedi alla tua dashboard aziendale [Satispay Business](https://dashboard.satispay.com/) (o per sandbox: [Satispay Sandbox Dashboard](https://staging.dashboard.satispay.com/)).
2. Vai nella sezione **Impostazioni** > **Sviluppatori** (Developers / API Keys).
3. Clicca su **"Crea Token di Attivazione"** o **"Aggiungi Dispositivo/POS"**.
4. Ti verrà mostrato un codice alfanumerico di 6 caratteri (es. `XK92LA`). Questo codice è monouso e scade dopo poco tempo.

### Passo 2: Esegui lo script automatico `satispay_setup.py`
Abbiamo incluso nel progetto uno script automatico che genera la chiave RSA a 4096 bit, contatta i server Satispay scambiando la chiave pubblica con il KeyID, e aggiorna automaticamente il file `.env`.

Apri il terminale ed esegui:
```bash
# Per ambiente reale (Produzione):
.venv/bin/python satispay_setup.py --token IL_TUO_CODICE_A_6_LETTERE

# Oppure se stai testando in Sandbox/Staging:
.venv/bin/python satispay_setup.py --token IL_TUO_CODICE --staging
```

Lo script effettuerà:
1. Creazione del file `satispay_private.pem` contenente la chiave privata (con permessi 600 di massima sicurezza).
2. Chiamata a `POST /g_business/v1/authentication_keys`.
3. Scrittura automatica nel file `.env`:
   ```env
   SATISPAY_KEY_ID="tuo-key-id-ricevuto"
   SATISPAY_PRIVATE_KEY_FILE="satispay_private.pem"
   SATISPAY_STAGING=false
   ```

## 3. Architettura Satispay: Polling Autonomo e SQLite

Il bot adotta un'architettura **100% autonoma** basata su **Polling e SQLite**, eliminando la necessità di Webhook, porte aperte o servizi di tunneling (come Cloudflare o Ngrok).

### Come funziona il Polling periodico
1. Tramite la `JobQueue` interna di Telegram, il bot interroga le API Satispay (`GET /g_business/v1/payments`) ogni 10 secondi (configurabile con `SATISPAY_POLL_INTERVAL`).
2. I pagamenti rilevati vengono memorizzati nel database SQLite locale (`satispay_history.db`).
3. **Primo avvio (DB vuoto)**: Sincronizza silenziosamente lo storico senza inviare notifiche a raffica in chat.
4. **Avvii successivi & Offline Catch-up**: Qualsiasi transazione non presente in SQLite viene riconosciuta come nuova, salvata ed inviata immediatamente in chat Telegram, anche se arrivata mentre il computer era spento!

### Comandi Telegram per lo Storico
- `/sat_list [data]`: Mostra la lista dei pagamenti di una data specifica (o oggi se omessa).
- `/sat_list_range <data_inizio> <data_fine>`: Mostra l'elenco dei pagamenti compresi nell'intervallo.
- `/sat_get <ID_Satispay>`: Richiama il messaggio di notifica con tutti i dettagli, permettendo di collegarlo con `/link <id_transazione>`.

## 3b. Integrazione SumUp

### Ottenere la API key
1. Accedi alla [Dashboard SumUp](https://me.sumup.com/) > **Impostazioni** > **Sviluppatori** (Toolkit / API Keys).
2. Crea una **secret key** (`sup_sk_...`) e inseriscila nel file `.env`:
   ```env
   SUMUP_API_KEY="sup_sk_..."
   SUMUP_MERCHANT_CODE=""        # opzionale: se vuoto viene letto automaticamente da GET /v0.1/me
   SUMUP_POLL_INTERVAL=15
   SUMUP_WAIT_TIMEOUT=300
   SUMUP_QR_ENABLED=true
   ```
   Se `SUMUP_API_KEY` è vuota l'integrazione SumUp è disattivata (nessun polling, nessun errore).

### Come funziona con il SumUp 3G+
- La Cloud API di SumUp (invio dell'importo al lettore) funziona solo con il **Solo**: con il **3G+** l'operatore digita l'importo sul terminale.
- In `/write`, con metodo **SumUp** ed **Entrata**, il bot chiede come incassare:
  - **💳 Attendi pagamento su terminale**: il bot interroga lo storico SumUp ogni 4 secondi e collega la prima transazione `SUCCESSFUL` avvenuta dopo l'inizio dell'attesa, **senza confrontare l'importo** (le transazioni già associate ad altre registrazioni sono escluse). Sul foglio resta l'importo inserito nel bot. Se la transazione non viene rilevata, il pulsante **⏩ Salta pagamento e registra** registra subito la riga senza ID SumUp (come per Satispay).
  - **🔗 Genera QR link di pagamento**: crea un checkout SumUp con pagina di pagamento ospitata (`hosted_checkout`), mostra il QR e attende lo stato `PAID`. Potrebbe richiedere l'abilitazione di Hosted Checkout sull'account. Se non funziona o crea confusione, imposta `SUMUP_QR_ENABLED=false` e il pulsante sparisce.
- L'ID salvato è il `transaction_code` SumUp, scritto nella **colonna P (`ID SumUp`)** del foglio. All'avvio la colonna viene aggiunta automaticamente alle intestazioni dei fogli esistenti.
- Polling in background e comandi `/sumup_list`, `/sumup_list_range`, `/sumup_get` funzionano come per Satispay; `/link` e `/unlink` riconoscono da soli se rispondi a una notifica Satispay o SumUp.

## 4. Stima dei Costi (Gemini Flash & API)

### Costo per l'Agente AI (Gemini Flash)
- **Modello Consigliato**: Gemini 1.5 Flash (o 2.0 Flash) è un modello estremamente veloce, con finestra di contesto ampia (fino a 1 milione di token) e un costo di utilizzo API trascurabile (~$0.075 per 1 milione di token di input e ~$0.30 per 1 milione di token di output).
- **Costo stimato per l'intero sviluppo e iterazione del progetto**: Tra **$0.05 e $0.25 USD**.
- **Idoneità**: Gemini Flash è più che sufficiente per gestire l'intero ciclo di vita del codice (implementazione di architetture modulari, unit testing, integrazione API Telegram/Google/Satispay). Passare questo piano dettagliato a Gemini 3.1 Pro Preview con Custom Tools assicura inoltre una precisione assoluta nell'esecuzione di tool complessi.

### Costo Servizi Esterni
- **Telegram Bot API**: 100% Gratuito.
- **Google Cloud / Sheets API**: Gratuito (il piano gratuito include fino a centinaia di migliaia di richieste al mese, ampiamente oltre il fabbisogno del registro).
- **Cloudflare Tunnels**: Gratuito.
- **Satispay Business API**: L'accesso alle API è gratuito (Satispay applica unicamente le sue tariffe standard di commissione sulle transazioni incassate).

## 5. Note Operative e Best Practices

### Gestione dei Log e Sessioni
- Ad ogni avvio del bot viene generato un file di log con timestamp in `logs/bot_YYYYMMDD_HHMMSS.log`.
- La cartella `logs/` e tutti i file `.log` sono esclusi da Git tramite `.gitignore` per evitare di tracciare cronologie locali o dati sensibili.

### Google Spreadsheet ID
- Il parametro `GOOGLE_SPREADSHEET_ID` nel file `.env` accetta sia l'ID pulito del documento (es: `1DHrn29h...`) sia l'intero URL di condivisione di Google Drive (es: `https://docs.google.com/spreadsheets/d/.../edit`). Il bot pulisce ed estrae automaticamente l'ID valido.


### Formato Date su Google Sheets
- Tutte le date salvate sul foglio di calcolo (colonna B `Data e Ora` e colonna O `Data Registrazione`) adottano lo standard `DD/MM/YYYY HH:MM:SS` (`GG/MM/AAAA HH:MM:SS`).
- Gli input manuali dell'utente in formati alternativi (come `AAAA-MM-GG HH:MM`, timestamp ISO o senza secondi) vengono automaticamente normalizzati a questo standard prima del salvataggio.

### Doppia Cassa Contanti (Rossa e Blu)
- Il contante è diviso in **🔴 Cassa Rossa** (principale) e **🔵 Cassa Blu** (resto e deposito temporaneo). Le transazioni in contanti usano la Blu per default; il pulsante `🔴 Usa Cassa Rossa` nel passo del saldo aggiornato le sposta sulla Rossa (e `🔵 Usa Cassa Blu` torna indietro). Nelle macro YAML si può impostare `cash_box: red` nei `defaults`.
- Layout colonne del foglio: D `Cassa Rossa Iniziale`, E `Cassa Blu Iniziale`, I `Cassa Rossa Aggiornata`, J `Cassa Blu Aggiornata`.
- In ogni flusso (`/write`, macro, Satispay, SumUp) il bot chiede la conferma dei saldi di entrambe le casse. Per i pagamenti Satispay/SumUp i saldi aggiornati coincidono con quelli confermati; per i contanti viene proposto il nuovo saldo della Cassa Blu.
- `/transfer` registra uno spostamento di contante tra le casse (metodo e flusso `Trasferimento`); `/cassa` mostra i saldi correnti.
- I fogli esistenti con la cassa unica vengono migrati automaticamente all'avvio: le colonne Blu vengono inserite e i vecchi saldi restano nella Rossa. Fai una copia del foglio prima del primo avvio.

### Performance, Caching e Reattività
- **Caching Cartella di Lavoro**: La cartella di lavoro (`spreadsheet`) e il foglio (`worksheet`) vengono istanziati una sola volta, azzerando le chiamate ridondanti all'API di Google Drive/Sheets.
- **Cache Dati e Batch Read**: Le letture sono raggruppate (`get_all_values()`) con cache a breve termine (TTL 10 secondi), auto-invalidata ad ogni operazione di scrittura (`add_transaction`, `link`, `unlink`).
- **Esecuzione Asincrona**: Le chiamate I/O di rete verso Google Sheets vengono eseguite in thread dedicati con `asyncio.to_thread()`, evitando di bloccare l'event loop di Telegram.
- **Riscontro Immediato Pulsanti**: Le callback dei pulsanti inline vengono confermate istantaneamente (`ack_callback_query()`), eliminando il tempo di caricamento percepito dall'utente.
